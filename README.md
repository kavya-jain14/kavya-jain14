## Flagship systems

### 01 / [TRINETRA](https://github.com/kavya-jain14/TRINETRA)

**An explainable control layer for UPI partners.** Three pre-authorisation risk lenses work with a state-safe payment ledger and status-first recovery orchestration.

`TypeScript` · `Fastify` · `PostgreSQL` · `Redis` · `BullMQ` · `React`

<details>
<summary><strong>Problem → system → proof</strong></summary>

- **Problem:** payment risk, provider timeouts, retries and reversals can create inconsistent decisions and duplicate movement.
- **System:** deterministic risk contracts, tenant-scoped durable intents, immutable state history, transactional outbox and bounded recovery workers.
- **Proof:** fixed allow, block, timeout-recovery, reversal and graph-risk journeys run against PostgreSQL and Redis with API integration coverage.
- **My role:** product and system architecture, backend integration and QA, with focused work around the durable ledger and recovery flow.

</details>

### 02 / [TRISHUL](https://github.com/kavya-jain14/TRISHUL)

**Continuous case-to-cash-out intelligence for authorised financial cyber-fraud response.** It converts reported transactions into provenance-backed financial-intelligence graphs.

`Node.js` · `PostgreSQL` · `Redis` · `runtime contracts` · `graph intelligence`

<details>
<summary><strong>Problem → system → boundary</strong></summary>

- **Problem:** after a complaint, investigators need to follow attributable exposure through commingled flows and prioritize probable exit zones.
- **System:** complaint-to-trace state machine, exposure ranges, behavioural and network evidence, continuous reforecasting and evidence anchors.
- **Boundary:** prediction is evidence-gated; location and time can independently abstain, and the product supports authorised decisions rather than autonomous freezes.
- **My role:** product and intelligence architecture, backend coordination, integration review and frontend QA.

</details>

### 03 / [MIRA](https://github.com/kavya-jain14/MIRA)

**An autonomous AI reliability and security editor.** MIRA discovers live developments, decides what deserves publication, remembers prior coverage and continues on a durable schedule.

`React` · `TypeScript` · `Node.js` · `SQLite` · `scheduled workers`

<details>
<summary><strong>Autonomy, made auditable</strong></summary>

- Live-source discovery passes through prompt-injection safety, domain gates and a frozen editorial rubric.
- Persistent fingerprints and similarity evidence prevent duplicate publishing under concurrency.
- Every published note exposes its sources, selection rationale, rejected alternatives and runtime history.
- **My role:** product, persona and editorial intelligence, shared contracts, frontend, integration, documentation and pitch.

</details>

### 04 / [Project Socrates](https://socrates-one-coral.vercel.app/)

**A teach-back learning platform built around the Socratic method.** Learners explain a concept to the AI, confront curated misconceptions and improve through deterministic feedback.

`Next.js 14` · `TypeScript` · `Prisma` · `PostgreSQL` · `cookie authentication`

<details>
<summary><strong>What makes it different</strong></summary>

- The learner teaches first; the system does not start by giving away the answer.
- Misconception handling and the scoring rubric make feedback repeatable rather than purely conversational.
- The seeded learning system includes concepts, curiosity questions, misconceptions and demo sessions.
- **My contribution:** learning flow, product UX, frontend polish, integration and deterministic evaluation work with Gargi.

</details>
